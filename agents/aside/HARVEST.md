# Aside 세션 수확

Aside 가 한 작업을 다른 에이전트가 대신 위키에 기록하는 절차다. 수확자는 셸과 위키 MCP 를 모두 가진
에이전트다(현재 `맥덱이`/Codex). 이 문서는 수확자가 따른다.

## 왜 대신 쓰는가

Aside 는 REPL 만 있고 셸이 없다. REPL 의 `fs` 는 Project·세션 루트에 하드 샌드박스되어 API key 파일을
읽지 못한다. `--permission full-access` 로도 뚫리지 않는다(실측: `Path escapes Project and session
roots`). 그래서 Aside 는 위키에 스스로 쓸 수 없고, Aside 를 위해 다른 에이전트가 쓴다.

이것은 "다른 에이전트의 Sessions 콜렉션은 읽기만 한다" 규칙의 **유일한 예외**다. 예외인 만큼 서명으로
누가 일했고 누가 받아적었는지 구분한다.

## 계정과 콜렉션

| Aside 계정 | 에이전트 | 콜렉션 | 성격 |
|---|---|---|---|
| `u0` | 맥사이드 | `맥사이드 Sessions` | 개인 |
| `u1` | 업사이드 | `업사이드 Sessions` | 회사 |

계정 폴더가 다르므로 섞일 여지가 없다. `harvest.mjs` 가 계정에서 에이전트 이름을 정한다. 임의로 바꾸지 않는다.

## 절차

```bash
node agents/aside/harvest.mjs status                 # 남은 세션 수
node agents/aside/harvest.mjs list --limit 10        # 아직 안 올린 세션 (JSON)
node agents/aside/harvest.mjs read <account> <id>    # 그 세션의 추려낸 대화
node agents/aside/harvest.mjs mark <account> <id> --doc <문서 URL>
node agents/aside/harvest.mjs mark <account> <id> --skip "<이유>"
```

세션 하나당 이 순서로 한다.

1. `list` 로 후보를 받는다. `firstMessage` 로 대략 무슨 일인지 본다.
2. `read` 로 전문을 읽는다. 길면 `--max` 로 줄인다.
3. **남길지 판단한다.** 남기지 않기로 했으면 `mark --skip "<이유>"` 로 끝낸다.
4. 남길 것이면 아래 규칙대로 문서를 쓰거나 기존 문서에 이어 쓴다.
5. `mark --doc <URL>` 로 표시한다. **문서를 쓴 뒤에 표시한다.** 먼저 표시하면 실패했을 때 영영 빠진다.

## 남기지 않는 것

- 사용자 지시가 없는 빈 세션(`harvest.mjs list` 가 이미 거른다).
- 잡담, 단순 질의응답, 한 번 보고 끝나는 조회("이 탭 뭐야", "이 페이지 열어줘").
- 실패해서 아무것도 안 남은 시도. 단, **왜 실패했는지가 다음에 쓸모 있으면 남긴다.**

목표가 있거나, 여러 단계를 거쳤거나, 나중에 누가 결과를 찾을 작업을 남긴다.

## 문서 쓰는 법

**먼저 검색한다.** 해당 콜렉션에서 같은 작업의 문서를 찾고, 있으면 새로 만들지 말고 `## Update` 를
append 한다. 세션이 여러 개로 나뉘어도 같은 작업이면 한 문서다.

- **제목**: `YYYY-MM-DD · <작업 요약>`. 날짜는 세션의 `startedAt` 현지 날짜.
- **icon**: 주제 이모지 1개.
- **첫 줄**: `작성자: <에이전트> · 기록: 맥덱이 · 상태: <상태>`
  - 일한 것은 Aside 에이전트이고 받아적은 것이 수확자다. 둘 다 적는다.
  - 상태: 🟡 진행 중 / ✅ 완료 / 🔴 차단됨 / ⚪ 대기 / ⚫ 취소. 세션이 목표를 달성하고 끝났으면 ✅.
- **골격**: `## 배경` → `## 완료 조건` → `## Update — <YYYY-MM-DD HH:MM KST> · mbp · aside:<account>`
  → 끝난 작업이면 `## 완료 기록`
- **마지막 줄**: `최종 갱신: <에이전트> · 기록: 맥덱이 · <YYYY-MM-DD HH:MM KST>`

Update 제목에 `aside:<account>` 를 붙여 어느 계정 세션에서 온 것인지 남긴다. 세션 id 도 본문에 적어
나중에 원본을 찾을 수 있게 한다.

## 내용 밀도

사용자가 나중에 자기 일을 재구성할 수 있을 만큼 **자세히** 쓴다. 무엇을 하려 했는지, 어떤 화면과 데이터를
거쳤는지, 무엇을 판단했고 왜 그렇게 했는지, 결과가 무엇인지. "조회했다" 같은 한 줄 요약으로 줄이지 않는다.

## 회사 계정(`u1` / 업사이드) 추가 규칙

`업사이드 Sessions` 콜렉션 overview 가 원본 규정이다. 요지:

- 업무 내용은 자세히 쓰되, **사내 문서·티켓·메일·채팅의 본문을 그대로 옮기지 않는다.** 읽고 이해한 것을
  정리해 쓰고, 원문 위치는 시스템 이름과 문서 제목 수준의 포인터로 남긴다.
- 스크린샷·화면 캡처 원본을 넣지 않는다. 필요한 구조는 말이나 표로 옮긴다.
- 비밀값과 사내 시스템 접속 정보는 어디에도 쓰지 않는다.
- 판단이 서지 않으면 그 세션은 `mark --skip` 하고 사용자에게 묻는다.

개인 계정 세션이라도 회사 자료를 다뤘으면(회사 계정으로 로그인한 구글 시트 등) 이 규칙을 같이 적용한다.

## 비밀값

Aside 세션 전문에는 메일 본문, 토큰, 쿠키가 섞여 있을 수 있다. 위키에 붙이기 전에 항상 확인한다.
API key·토큰·비밀번호·계정 접속 정보는 저장 경로와 변수명, 끝 4자리까지만 쓴다.

## 실패했을 때

문서 쓰기에 실패하면 `mark` 하지 않는다. 다음 실행에서 다시 후보로 나온다. 같은 세션이 계속 실패하면
그 세션 id 와 에러를 사용자에게 보고하고 넘어간다.

## 흔한 실수

- **`\n` 을 문자 그대로 쓰지 않는다.** MCP `create_document` 의 `text` 는 마크다운 원문이다. 줄바꿈은
  실제 개행으로 넣는다. `"...\n원본 세션:"` 처럼 쓰면 문서에 `\n` 이 그대로 보인다.
- `mark` 를 문서 쓰기보다 먼저 하지 않는다.
- 같은 작업인데 세션이 나뉘었을 때 문서를 새로 만들지 않는다. 먼저 검색한다.
