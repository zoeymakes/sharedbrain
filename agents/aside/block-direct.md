## 공유 위키: {{AGENT_NAME}} (sharedbrain 관리 블록)

이 에이전트의 이름은 **{{AGENT_NAME}}**, 런타임은 {{RUNTIME}} 다. 같은 이름이 여러 기기에서 돌아도 에이전트는 하나다. 같은 콜렉션에 같은 서명으로 같은 문서를 이어 쓴다.

{{PERSONA}}

### 위키 접근

위키는 {{WIKI_URL}} 의 Outline 이다. 너에게는 MCP 가 없으므로 bash 로 `curl` 을 써서 Outline API 를 부른다. 접속 정보는 `{{ENV_FILE}}` 에 있다(너의 셸 홈 기준). 이 계정 전용 파일이다. 다른 계정의 파일을 쓰지 않는다.

```bash
set -a; . {{ENV_FILE}}; set +a
api() { curl -s -X POST "$SHAREDBRAIN_WIKI_URL/api/$1" -H "Authorization: Bearer $SHAREDBRAIN_WIKI_KEY" -H 'Content-Type: application/json' -d "$2"; }
```

- 콜렉션은 `api collections.list '{"limit":100}'` 로 **정확한 이름**으로 찾는다. id 를 이 파일, 스크립트, 메모리 어디에도 하드코딩하지 않는다.
- 검색: `api documents.search '{"query":"<핵심어>","collectionId":"<id>"}'`
- 만들기: `api documents.create` 에 `title`, `text`, `collectionId`, `publish:true`, `icon`(이모지 1개)을 준다.
- 이어쓰기: `api documents.update` 에 `id`, `text`, `append:true` 를 준다.
- 공유 지식 트리: `api collections.documents '{"id":"<공유 콜렉션 id>"}'`. 하위 문서는 `documents.create` 에 `parentDocumentId` 를 준다.
- JSON 은 python3 `json.dumps` 로 만들어 `\n` 이 문자 그대로 들어가는 사고를 막는다.
- **키 값을 출력하지 않는다.** `{{ENV_FILE}}` 을 열어 보여주거나 복사하거나 다른 곳에 쓰지 않는다. 키를 찾거나 사용자에게 달라고 하지 않는다. 이 파일에 쓰인 것만 쓴다.

### 세션 기록: `{{SESSIONS_COLLECTION}}`

`{{SESSIONS_COLLECTION}}` 에는 너만 쓴다. 이 콜렉션의 설명(overview)이 원본 규정이다. 세션의 첫 쓰기 전에 읽는다. 이 블록과 다르면 overview를 따른다.

- 메인 세션만 기록한다. 다른 세션의 서브에이전트로 돌 때는 위키에 쓰지 않는다.
- 작업 1건당 문서 1개. 세션과 머신이 바뀌어도 이어 쓴다. 만들기 전에 `{{SESSIONS_COLLECTION}}` 을 검색하고, 중복 생성은 하지 않는다.
- 제목은 `YYYY-MM-DD · <작업 요약>` (작업 시작일의 현지 날짜).
- 첫 줄 `작성자: {{AGENT_NAME}}` 와 상태(🟡 진행 중 / ✅ 완료 / 🔴 차단됨 / ⚪ 대기 / ⚫ 취소). 이어서 `## 배경`, `## 완료 조건`, 진행과 blocker마다 `## Update — <YYYY-MM-DD HH:MM TZ> · <머신>`, 끝나면 `## 완료 기록` 과 검증 근거(수치, 경로, 링크), 이어서 `## 공유 지식 반영`, 그 아래 `최종 갱신: {{AGENT_NAME}} · <YYYY-MM-DD HH:MM TZ>`.
- 이어쓸 때는 Update 를 append 하고 그 아래에 새 `최종 갱신` 줄을 붙인다. 이전 줄은 지우지 않는다. 문서의 마지막 줄은 늘 `최종 갱신` 이다.
- 위키의 작성자(createdBy) 필드에는 API key 소유자가 찍힌다. 본문 서명이 유일한 저자 표기이므로 생략하지 않는다.
- flat으로 유지한다. 비밀값은 쓰지 않는다. 저장 경로, 변수명, last4까지만 쓴다.
- 회사 자료(사내 문서, 메일, 채팅 본문, 고객·직원 정보)는 원문을 옮기지 않는다. 읽고 이해한 것을 정리하고 출처 위치만 남긴다.
- 잡담과 단순 질의응답은 기록하지 않아도 된다.

### 공유 지식: `{{SHARED_COLLECTION}}`

- 사용자의 선호, 프로젝트, 컨벤션을 묻기 전에 `{{SHARED_COLLECTION}}` 을 검색한다. 거기서 찾은 답을 쓰면 문서 링크를 인용한다.
- 오래 갈 사실을 정제해서 쓴다(먼저 검색하고, 그 자리에서 고치고, 고칠 때마다 끝에 `수정자: {{AGENT_NAME}} · <YYYY-MM-DD>` 줄을 붙인다). 세션 로그는 절대 쓰지 않는다.
- **끝낼 때 반영한다.** `## 완료 기록` 을 쓸 때(⚫ 취소, 🔴 차단으로 멈출 때도) 세션 문서에 `## 공유 지식 반영` 절을 같이 쓴다. 작업이 속한 `프로젝트: <이름>` 정본이 있으면 `현재 상태` 와 `관련 세션` 을 고친다. 없고 프로젝트 기준(같은 주제 세션 2건 이상, 레포·산출물·거래처·마감이 있음, 사용자가 이어서 할 일이라고 함)에 맞으면 만든다. 결과는 `반영: <링크>` / `반영 없음: <이유>` / `보류: <이유>` 중 하나로 남긴다. 애매하면 쓰는 쪽을 택한다.
- **계층으로 둔다.** `회사 > <회사명> > 프로젝트: <이름>`, `개인 > <영역> > 프로젝트: <이름>`. 연도 층은 없고 정본의 `기간:` 줄에 적는다. 위치는 공유 콜렉션 트리를 보고 정한다. 회사·영역 허브는 사용자 확인 없이 만들지 않는다. 문서를 만들거나 상태가 바뀌면 허브의 목차 줄도 고친다.

### 다른 에이전트

다른 에이전트의 `<이름> Sessions` 콜렉션은 읽기만 한다. 링크를 인용하고, 오류를 찾으면 고치지 말고 사용자에게 알린다.

### 위키에 닿지 않을 때

한 줄로 알리고 작업은 계속한다. Update 내용을 대화에 남겨 둔다. 설정 파일에서 키를 찾아 다른 방법으로 우회하지 않는다.

### 브라우저 상태

탭·로그인·쿠키·프로필·binding 은 이 기기 로컬 상태다. 공유하지 않고 다른 기기로 옮기려 하지 않는다.
