# 에이전트 지도

## 세 층

| 층 | 무엇 | 왜 따로 두는가 |
|---|---|---|
| `agents` | 정체성을 가진 실행 주체 | 위키 콜렉션과 권한의 단위 |
| `environments` | 에이전트를 실행하는 환경 | 같은 에이전트가 환경에 따라 다르게 기록해야 한다 |
| `daemons` | 상시 자동화 프로세스 | 에이전트는 아니지만 장애 추적에 필요하다 |

## 정체성의 단위

**소프트웨어가 아니라 이름이 단위다.**

- 같은 이름이 여러 기기에서 돌아도 **에이전트는 하나**, 콜렉션도 하나다.
- 같은 런타임이라도 프로필이 다르면 **다른 에이전트**다. Hermes의 비서 프로필과 투자 프로필은
  역할·권한·기록 위치가 다르므로 registry 로우가 둘이다.
- 런타임을 옮기면(OpenClaw → Hermes) 콜렉션은 유지하고 주입 위치만 바꾼다. 이전 로우는 `retired` 로 남긴다.

## 환경을 분리하는 이유

Orca 같은 ADE는 한 프롬프트를 여러 에이전트에게 fan-out 하고 각각 독립 worktree에서 돌린다.
이때 `## Update — <시각> · <기기>` 만으로는 다섯 개 시도 중 어느 것이었는지 알 수 없다.
그래서 병렬 환경에서는 `orca:<worktree>` 를 함께 적는다.

## 런타임별 주입 위치

| 런타임 | 주입 위치 | 인증 | 단계 |
|---|---|---|---|
| Claude Code | `~/.claude/CLAUDE.md` | OAuth 또는 API key | 09 |
| Codex | `~/.codex/AGENTS.md` | `codex mcp login` 또는 API key | 13 |
| Hermes | 프로필별 skill | API key (상시 실행, 브라우저 없음) | 14 |
| Aside | 계정별 `AGENTS.md` | handoff 파일 경유(위키 MCP 직접 소비 안 함) | 15 |
| OpenClaw | 에이전트별 지침 파일 | API key | 16 |

## 규칙의 단일 출처

모든 어댑터는 `agents/_shared/wiki-rules.ko.md` 를 치환해 주입한다. 런타임마다 복사본을 두지 않는다.
규칙을 고칠 때 한 곳만 고치면 다음 주입부터 모든 런타임에 반영된다.

## API key 분리

에이전트·기기 단위로 키를 만든다(`hermes-<기기>`, `codex-<기기>` 처럼).
사고가 나면 그 키만 폐기하면 되고, 위키의 API & Access 화면에서 어느 에이전트가 쓰는 키인지 바로 보인다.
