# 무엇을 공유하고 무엇을 기기에 두는가

"에이전트가 각 기기에서 만든 스킬·메모리·세션을 어디까지 공유해야 하나"에 대한 이 레포의 답이다.

## 한 줄 원칙

**기억은 공유하고, 실행 상태는 각 기기에 둔다.**

기억 = 무엇을 했고 무엇을 정했는가. 실행 상태 = 그것을 하던 프로세스가 어떤 모양이었는가.
앞은 재구성 가능하고 리뷰할 수 있다. 뒤는 런타임마다 형식이 다르고 동시에 쓰면 깨진다.

## 판정표

| 데이터 | 위치 | 판정 근거 |
|---|---|---|
| 작업 기록(세션 문서) | **공유 위키** | 다른 기기가 이어받는 유일한 통로 |
| 결정·정제된 지식 | **공유 위키** | 오래 가고 여러 에이전트가 참조 |
| 운영 규칙, registry | **Git** | 리뷰·롤백이 필요 |
| 공용 스킬 | **Git** (아래 절차) | 사람이 읽고 고칠 텍스트 |
| 기기·경로 종속 스킬 | **로컬** | 다른 기기에서 동작하지 않음 |
| 에이전트 메모리 | **로컬 + 선별 승격** | 아래 별도 절 |
| 세션 id, resume 상태 | **로컬 고정** | 런타임마다 형식이 달라 섞으면 깨짐 |
| 실행 프로세스, PTY, tmux | **로컬 고정** | 파일 복제로 이식 불가 |
| 인증 토큰, 쿠키, 브라우저 프로필 | **로컬 고정** | 동기화하면 사고 |
| 캐시, 인덱스, 로그 | **로컬 고정** | 경로 종속, 동시 쓰기 충돌 |

## 애매한 것을 판정하는 3가지 질문

1. **다른 기기에서 그대로 유효한가?** 절대경로·호스트명·기기별 도구 버전에 의존하면 로컬이다.
2. **두 기기가 동시에 써도 안전한가?** SQLite·lock·WAL·인덱스가 얽히면 로컬이다.
3. **사람이 읽고 리뷰할 수 있는가?** Markdown/YAML이면 공유 후보, 바이너리·자동 생성물이면 로컬이다.

셋 다 "예"일 때만 공유한다.

## 공용 스킬 공유 절차

런타임마다 스킬 경로가 다르므로 **한 곳에 두고 심링크**한다. 복사본을 여러 벌 두지 않는다.

```text
<공유 Git 레포>/skills/<스킬이름>/SKILL.md    ← 정본 (리뷰·PR 대상)
```

각 기기에서 런타임별 경로에 심링크한다.

| 런타임 | 스킬 경로 |
|---|---|
| Claude Code | `~/.claude/skills/<이름>` |
| Hermes | `~/.hermes/skills/<이름>` (프로필별은 `~/.hermes/profiles/<프로필>/skills/`) |
| Codex | 스킬 개념 없음. 규칙은 `~/.codex/AGENTS.md` 블록으로 |

### 처음 한 번 (기기별)

```bash
# 1. 공유 레포를 만든다 (private 권장). 이미 있으면 clone 만 한다.
gh repo create <내계정>/agent-skills --private
git clone https://github.com/<내계정>/agent-skills.git ~/agent-skills
mkdir -p ~/agent-skills/skills

# 2. 런타임별 스킬 경로에 심링크한다
ln -s ~/agent-skills/skills/<이름> ~/.claude/skills/<이름>
ln -s ~/agent-skills/skills/<이름> ~/.hermes/skills/<이름>

# 3. 확인
ls -l ~/.claude/skills/<이름>      # -> ~/agent-skills/skills/<이름> 로 보여야 한다
```

### 세션 시작·종료

```bash
cd ~/agent-skills && git pull --rebase                 # 시작할 때
cd ~/agent-skills && git add -A && git commit -m "skill: <무엇>" && git push
```

기기마다 `~/agent-skills` 를 두고 심링크만 걸므로 스킬 정본은 레포에 하나뿐이다.
고치면 정본에서 고치고 push 하고, 다른 기기는 다음 pull 에서 받는다.

규칙:

- 스킬 디렉터리 안에 캐시·인덱스·생성물이 생기는 런타임이면 그 하위 경로를 `.gitignore` 에 넣는다.
- 기기 전용 스킬은 공유 레포에 올리지 않는다. 판정은 위 3가지 질문으로 한다.
- 스킬을 고치면 정본에서 고치고 push 한다. 각 기기는 세션 시작 시 pull 한다.

## 메모리는 왜 다른가

에이전트 메모리(Hermes memory, Claude Code memory 등)는 **기억이지만 자동 누적된다**.
그대로 동기화하면 기기별 중복·모순이 쌓이고 검색 품질이 떨어진다. 그래서:

- **원본은 로컬**에 둔다. 동기화하지 않는다.
- 오래 갈 사실(사용자 선호, 프로젝트 상태, 컨벤션, 결정)만 **공유 지식 콜렉션으로 승격**한다.
- 승격은 자동이 아니라 검토를 거친다. 승격 권한은 `wiki_access: read-write` 인 에이전트에게만 준다.
- 다른 기기의 에이전트는 메모리를 복사받는 대신 **공유 지식을 검색**해 같은 맥락을 얻는다.

즉 메모리는 "공유 대상"이 아니라 "승격 후보의 원천"이다.

## 세션을 그대로 이어받고 싶다면

이 레포는 세션 파일 동기화를 지원하지 않는다. 런타임끼리 형식이 다르고(Codex는 resume마다 새 thread_id,
Claude는 session_id) 동시 쓰기에서 깨진다.

정말 **실행 중인 세션 자체**가 필요하면 파일을 복제하지 말고 **원래 호스트에 원격 접속**한다
(Tailscale/SSH + tmux). 그러면 세션은 한 곳에만 존재하고 여러 기기가 그 화면을 공유한다.
