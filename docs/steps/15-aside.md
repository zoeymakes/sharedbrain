# 15단계: Aside 에이전트 연결

스킬: `kna-15-aside`. 선택 단계이며 Aside를 쓸 때만 돈다.

어댑터 계약: [`agents/aside/ADAPTER.md`](../../agents/aside/ADAPTER.md)

## Aside만 방식이 다르다

`aside mcp` 는 Aside를 MCP **서버로 노출**하는 명령이다. 외부 MCP 서버(위키)를 소비하는 클라이언트
기능은 확인되지 않았다. 그래서 Aside는 위키에 직접 쓰지 않고 **handoff 파일을 거친다.**

```text
Aside (브라우저 작업)
  └─ 작업 끝/중단 시 handoff 파일 작성
        ~/.sharedbrain/handoff/aside/<계정>/<날짜>-<작업>.md
             ↓ 같은 기기의 Hermes 또는 Claude Code가 읽음
        위키의 `<에이전트> Sessions` 에 규칙대로 기록
             ↓
        handoff 파일을 archive/ 로 이동 (중복 기록 방지)
```

## 브라우저 상태는 공유하지 않는다

탭·로그인·쿠키·브라우저 프로필·binding은 이식할 수 없다. 이것들을 동기화하려 하지 않는다.
인증된 화면의 실제 조작은 그 기기에서 계속하고, 다른 기기는 정리·판단·후속 문서 작업만 이어받는다.

## 계정 분리

Aside는 계정(`u/0`, `u/1` …)마다 별도 브라우저 프로필을 갖는다. `aside account` 로 확인한다.
개인 계정과 회사 계정을 함께 쓰면 **회사 계정의 규칙 블록에는 반출 금지 문구를 반드시 넣는다.**

## 회사 계정 규칙 (필수)

- 회사 화면의 원문·고유명·내부 URL·수치·스크린샷을 위키나 handoff 파일에 넣지 않는다.
- 업무명·문제·판단·현재 상태·정본 위치 포인터만 비식별화해 남긴다.
- 판단이 서지 않으면 기록하지 않고 사용자에게 묻는다.

## 검증

```bash
aside account
ls -la ~/.sharedbrain/handoff/aside/<계정>/
```

handoff 파일 1건을 만들고, 지정한 에이전트가 그것을 읽어 위키에 문서를 만든 뒤
그 문서를 다시 검색해 찾고 handoff가 `archive/` 로 옮겨지면 통과다.

## 상태

명령은 실제 설치본에서 확인했지만 **종단 실행은 아직 검증되지 않았다.**
