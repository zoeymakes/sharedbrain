# 14단계: Hermes 에이전트 연결

스킬: `kna-14-hermes`. 선택 단계이며 Hermes를 쓸 때만 돈다.

어댑터 계약: [`agents/hermes/ADAPTER.md`](../../agents/hermes/ADAPTER.md)

## 프로필 하나가 에이전트 하나다

Hermes는 프로필마다 별도 에이전트로 다룬다. 비서 역할 프로필과 특정 영역 리포트 프로필은
역할·권한·기록 위치가 다르므로 **각각 이름·콜렉션·권한을 따로** 갖는다. 프로필마다 이 단계를 반복한다.

## MCP 등록

상시 실행 서버에는 브라우저가 없으므로 API key를 쓴다. 키 이름을 `hermes-<프로필>-<기기>` 처럼
에이전트별로 만들면 사고 시 그 키만 폐기할 수 있다.

```bash
hermes mcp add <서버이름> --url https://<위키>/mcp
hermes mcp list
hermes mcp test <서버이름>
```

직접 편집해야 하면 `~/.hermes/config.yaml` 의 **최상위** `mcp_servers:` 아래에 넣는다.
`mcp:` 는 보조 모델 설정이라 다른 키다 — 거기에 넣으면 서버가 등록되지 않는다.

```yaml
mcp_servers:
  <서버이름>:
    url: https://<위키>/mcp
    headers:
      Authorization: "Bearer ${OUTLINE_API_KEY}"
```

HTTP 여부는 `url:` 키 존재로 결정된다. `transport:` 는 `sse` 를 쓸 때만 지정한다.

## 규칙을 skill 로 주입하는 이유

Hermes는 매 턴 skill 목록을 노출하고 조건이 맞을 때 본문을 로드한다. 규칙을 skill 로 두면:

- 위키에 쓸 일이 있을 때만 규칙 본문이 로드되어 평상시 토큰을 낭비하지 않는다.
- 프로필별로 다른 권한(정본 승격 가능 / 자기 영역만)을 다른 skill 로 분리할 수 있다.

주입 위치는 기본 프로필이면 `~/.hermes/skills/`, 그 외는 `~/.hermes/profiles/<프로필>/skills/` 다.

## 권한

registry의 `wiki_access` 를 그대로 반영한다.

| 권한 | 뜻 |
|---|---|
| `read-write` | 공유 지식 정본을 고칠 수 있다. 승격 전 사용자 확인은 유지한다 |
| `자기 영역만` | 자기 Sessions와 지정된 주제 문서만 쓴다. 정본 승격을 하지 않는다 |
| `read-only` | 검색·인용만 한다 |

정본 승격 권한은 한 에이전트에게만 주는 것을 권한다. 여러 에이전트가 같은 문서를 고치면
"어느 쪽이 맞는지" 판단할 근거가 사라진다.

## 검증

이 단계는 다음이 모두 확인돼야 `done` 이다.

1. MCP 등록 확인 명령이 위키 서버를 보여준다.
2. 그 런타임의 새 세션에서 `list_collections` 가 콜렉션 목록을 반환한다.
3. 규칙대로 세션 문서 한 건이 만들어진다.
4. 다시 검색해 그 문서를 찾고 `## Update` 를 덧붙일 수 있다.

실패하면 `done` 으로 표시하지 않는다. 상세 절차는 스킬 파일에 있다.

## 상태

명령·설정 스키마는 실제 설치본에서 확인했지만, **종단 실행(위키 생성 → 연결 → 기기 간 이어받기)은
아직 검증되지 않았다.** 따라 하다 막히면 이슈로 알려 주면 고친다.
